# Письмо после успешной демооплаты

Письмо создаётся только при подтверждённом успехе и содержит номер заказа, названия, варианты, количество, цены, доставку и итог. Текст ясно обозначает демозаказ без списания денег и отправления товаров. Телефон, адрес и комментарий в Resend не передаются.

Интеграция подготовлена для Resend. API-ключ отсутствует: настоящая доставка в ящик пока не проверена. До настройки на странице результата написано «Письмо подготовлено, но почтовый сервис пока не настроен».

## Подключение

1. Создайте аккаунт [Resend](https://resend.com) и API-ключ с правом отправки.
2. В .env.local укажите:

```dotenv
EMAIL_MODE=resend
RESEND_API_KEY=ваш_секретный_ключ
EMAIL_FROM="Письма и звёзды <onboarding@resend.dev>"
```

Ключ остаётся на сервере. Не отправляйте его в чат, не добавляйте NEXT_PUBLIC_ и не коммитьте .env.local.

3. Перезапустите npm run dev.
4. Для первого теста в форме заказа укажите именно email, на который зарегистрирован аккаунт Resend, и завершите успешную демооплату. Отправитель onboarding@resend.dev разрешён только для такого получателя: [официальное ограничение](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain).
5. Проверьте входящие и спам. Интерфейс сообщает лишь, что почтовый сервис принял письмо: это не подтверждение попадания во входящие.

Для доставки на любую указанную почту подтвердите собственный домен в Resend через необходимые DNS-записи и замените EMAIL_FROM адресом этого домена. Регистрация домена и платные услуги не подключались.

## Надёжность

SQLite хранит одну запись mail_outbox на заказ. Она создаётся атомарно с успешным статусом оплаты, поэтому сбой отправки не отменяет оплату и не теряет письмо. Поля письма фиксируются по снимку заказа; отправитель фиксируется при первой попытке.

Отправка выполняется сервером через POST https://api.resend.com/emails после ответа покупателю. Секрет не доступен браузеру. Две параллельные обработки защищены двухминутным lease; повторный запрос использует один Idempotency-Key order-receipt/{UUID}. Принятое письмо больше не отправляется. Не выводим email, ключ, тело письма или подробности ошибки провайдера в публичный ответ и логи.

При сбое — увеличивающийся интервал повторов, до пяти попыток. Если окно повторов приближается к истечению, запись переводится в review и автоматическая отправка прекращается: Resend хранит ключи идемпотентности [24 часа](https://resend.com/docs/dashboard/emails/idempotency-keys). После 23 часов от первой попытки повторяемость требует ручной проверки в кабинете, чтобы не отправить дубль.

После перезапуска очередь остаётся в базе. Открытая страница заказа повторно обрабатывает ожидающие/неудачные письма; для обработки без открытого браузера выполните:

```sh
npm run mail:flush
```

Команда читает .env.local и обрабатывает до 20 записей. Для будущего хостинга можно запускать её раз в минуту отдельным заданием сервера. Планировщик на текущем этапе не настраивался.

Если первая попытка была с неправильным EMAIL_FROM, тело запроса автоматически не меняется, чтобы сохранить идемпотентность. Проверка записи и ответа Resend требуется разработчику. Не удаляйте запись очереди и не меняйте ключ наугад после неопределённого сетевого исхода.

## Проверка и границы

Тесты проверяют состав и суммы, адрес получателя, отсутствие письма до успеха, единственную запись, параллельных работников, сетевые/HTTP ошибки, таймер повтора и остановку за пределами окна. Адаптер проверен на подставленном ответе Resend; реальная отправка требует вашего ключа. Тесты браузера принудительно отключают настоящую почту.

Никаких настоящих писем во время разработки без настроенных учётных данных не отправлялось. Вебхуки доставки/отказа от Resend не подключены; sent означает принятие API, а не подтверждённую доставку во входящие.
