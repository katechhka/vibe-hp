# Управление мастерской

Адрес: http://127.0.0.1:3000/admin. Один аккаунт admin, без регистрации покупателей и дополнительных ролей.

## Первый вход

В текущем проекте аккаунт уже создан. Временный пароль находится в закрытом локальном файле .qa/admin-access.txt. Он не включается в исходники или браузерный код. Войдите, откройте «Доступ», смените пароль и удалите файл с временным паролем.

Для нового чистого окружения:

```sh
npm run admin:setup
npm run dev
```

Команда создаёт аккаунт только если его ещё нет. Существующий пароль не перезаписывается. В .env.local записывается исходный scrypt-хеш, а не пароль. После смены пароля актуальный хеш хранится в SQLite. Все прежние сеансы завершаются. Удаление cookies не сбрасывает пароль.

ADMIN_PASSWORD_HASH нужен для первоначального создания аккаунта на новой базе. При переносе существующей базы переносите сам файл SQLite: он содержит актуальный пароль, товары, остатки и заказы. Старый исходный хеш из окружения не заменяет актуальный пароль.

Сеанс длится 8 часов; cookie HttpOnly, SameSite=Strict, при HTTPS — Secure. Неверные попытки входа ограничены: 10 за 15 минут для всей админки. Перед публичным размещением можно добавить ограничение по IP на reverse proxy; заголовкам клиента приложение не доверяет.

## Товары

«Товары → Изменить» позволяет редактировать название, категорию, цену, описание, характеристики, срок изготовления, варианты, подпись карточки и фотографии.

- Цена — в рублях, до двух знаков после запятой; заказ рассчитывается сервером в целых копейках.
- Адрес существующего товара закреплён, чтобы не ломать ссылки. Для нового товара используйте латинские буквы, цифры и дефисы.
- Физический остаток включает зарезервированные товары.
- Резерв — количество в ожидающих заказах.
- Доступно — физический остаток минус резерв.
- Остаток нельзя уменьшить ниже резерва. Варианты нельзя менять, пока товар присутствует в ожидающем заказе.
- Если товар оплатили или изменили в другой вкладке после открытия редактора, сохранение отклоняется. Обновите список и откройте редактор заново, чтобы не вернуть проданный остаток.
- «Показывать в магазине» управляет видимостью. Скрытие не удаляет товар и не меняет старые заказы. Новые заказы со скрытым товаром запрещены; уже оформленные заказы сохраняют условия покупки.
- Новая вещь сначала создаётся скрытой. Заполните название, цену и краткое описание; фотографии можно добавить позже. Включите показ, когда вещь готова.

Изменения в SQLite не требуют пересборки. Новое открытие страницы получает актуальные товары; уже открытая витрина обновляет каталог при возвращении фокуса и раз в 30 секунд. Цены и наличие при оформлении всегда проверяются сервером. Заказы сохраняют цены, наименования, варианты и изображения на момент оформления.

Исходный src/data/catalog.ts теперь служит начальным наполнением новой базы и источником категорий/тарифов. Его изменение не перезаписывает существующие товары.

## Фотографии

Загружайте собственные разрешённые изображения JPEG, PNG, WebP или AVIF, не более 8 МБ и минимум 300 × 300 px. Сервер проверяет формат и ограничивает число пикселей, исправляет ориентацию, удаляет исходные метаданные, уменьшает изображение до 1600 px и сохраняет WebP.

Первое фото — обложка. Для другого фото можно выбрать «Сделать обложкой». Заполните описание изображений для незрячих. После загрузки обязательно сохраните товар.

Файлы хранятся вне public в UPLOADS_PATH, по умолчанию data/uploads. Публичный маршрут /media/<хеш>.webp отдаёт только изображение с допустимым именем. Произвольные пути и доступ к базе запрещены. Файлы не удаляются при замене фотографий: на них могут ссылаться старые заказы. Автоматическая очистка не используется.

## Заказы

Раздел показывает последние 100 заказов. «Посмотреть» открывает состав, сохранённые цены, доставку, контакты и комментарий покупателя. Контакты доступны только вошедшему администратору; публичный API заказа их не возвращает.

Оплату нельзя вручную отметить успешной из админки. Статус меняется только через локальный симулятор своего заказа или подтверждённый ответ API тестовой ЮKassa. При просмотре админка показывает сохранённый статус; для сверки закрытых покупателем платежей используйте payments:sync или будущие уведомления провайдера.

## Проверка

```sh
npm test
npm run build
npm run test:admin
```

test:admin запускает отдельный production-сервер на порту 3006, временную базу, отдельную папку фотографий и тестовый пароль. Почта и внешний платёжный сервис отключены. Основные данные магазина и пароль не меняются.

Проверяются защита доступа, неправильный пароль, cookie и Origin, редактирование цены, запрет уменьшения резерва, устаревшая форма, сохранность старых заказов, новый товар с загрузкой фото, его покупка, защита контактов, смена пароля, перезапуск и адаптивность. Отчёт — admin-check-results.json; изображения — screenshots/admin-*.

## Размещение

Нужен один Node-сервер с постоянной SQLite и постоянной папкой UPLOADS_PATH. Резервная копия должна включать согласованный SQLite backup и фотографии. Не включайте .env.local, .qa/admin-access.txt и базу в исходники или публичную папку.

Это небольшая админка для одной мастерицы: нет нескольких ролей, восстановления через email, массового импорта, фискальных чеков и управления настоящей доставкой. Публикация остаётся отдельным этапом; реальные списания отключены.

## Обновление формы товара

Обязательны только название, цена и краткое описание. Для новой вещи адрес формируется из названия автоматически: кириллица переводится в латиницу, слова разделяются дефисами, при совпадении добавляется номер. При переименовании существующей вещи адрес сохраняется.

Фотографии необязательны: без них используется собственная иллюстрация «Фото скоро появится». Можно загрузить от одной до трёх фотографий; первая загрузка заменяет заглушку. Пустые подробное описание и характеристики не показываются покупателю. Начальный остаток — 0, новую вещь можно спокойно подготовить перед публикацией.

Возврат к списку доступен сверху и снизу редактора, а также через вкладку «Товары». Перед возвращением сохраните изменения, которые хотите оставить.
