# Этап 3: каталог, галереи, корзина и оформление

Сохранён дизайн этапа 2. Работа посвящена устойчивому поведению интерфейса.

## Что изменено

- Общая логика корзины в src/lib/cart.ts: проверка сохранённых данных, объединение дублей, ограничения целого количества и общего остатка разных вариантов.
- Добавление учитывает самое последнее состояние даже при нескольких синхронных вызовах. Неизвестные товары, варианты и недоступные позиции не принимаются.
- Изменения корзины синхронизируются через storage event между вкладками. Если хранение запрещено, появляется понятное предупреждение. При недоступном localStorage корзина сохраняется в памяти только до перезагрузки документа.
- Общие расчёты в целых копейках, единые тарифы для итогов и страницы доставки. Эти функции пока вызываются клиентом; серверного контроля цены ещё нет.
- Каталог использует URL как источник выбранных фильтров. Категория и сортировка поддерживают Назад/Вперёд; поиск обновляет текущую запись истории. Неизвестные значения категории и сортировки игнорируются.
- Количество на товаре ограничивается актуальным свободным остатком. Галерея поддерживает клавиатуру, горизонтальный свайп и объявления смены изображения; вертикальный жест не меняет фотографию. Карусель пересчитывает границы после изменения ширины и использует фактический gap.
- Оформление хранит разные адреса для пункта выдачи и курьера. Черновик прежнего формата мигрируется, типы и длины восстановленных значений проверяются, согласия после обновления не проставляются автоматически.
- Валидация контактов, активного адреса, согласий и длины комментария вынесена в src/lib/checkout.ts. Телефон с буквами и недопустимой длиной отклоняется; пробелы по краям email допускаются.

## Проверка

- npm test: 14 содержательных тестов расчётов, остатков, восстановления и валидации.
- npm run test:flows: 9 сценариев в Chrome, включая повреждённую корзину, 20 немедленных кликов, варианты, две вкладки, историю фильтров, независимые адреса и блокировку хранения.
- npm run test:ui: основной путь до проверки формы, 12 товаров и ширины 360/390/768/1024/1440 px. Результат и скриншоты обновлены.
- npm run build: production-сборка и TypeScript.

Машинные отчёты: flow-check-results.json и ui-check-results.json. Браузерные сценарии запускаются при работающем dev-сервере. Сенсорные жесты проверены синтетическими TouchEvent, а не на физическом телефоне.

## Честная граница этапа

Форма проверяет данные локально и не создаёт заказ. База, серверная валидация, защита доступа к заказам, идемпотентность и оплата — этап 4 и далее. /preview/payment остаётся набором макетов, не платёжной интеграцией. Внешние ключи для этого этапа не требуются. Публикация не выполнялась.
