# Vercel + Supabase: бесплатная портфолио-демоверсия

Оплата остаётся только тестовой. Vercel Hobby предназначен для личных некоммерческих проектов; этот магазин демонстрирует покупку без реальной продажи.

## Что подготовлено

- Асинхронное PostgreSQL-хранилище: товары, физические остатки, резервы, заказы, попытки оплаты, админка и очередь писем.
- Одни правила валидации товара для SQLite и PostgreSQL.
- Межпроцессная транзакционная блокировка небольшого магазина: создание заказа, повтор, подтверждение оплаты и редактирование остатков не расходятся между serverless-инстансами. HTTP-запросы к ЮKassa и Resend выполняются вне блокировки.
- Закрытая схема shop, недоступная через Data API ролям anon/authenticated.
- Приватный bucket product-images. Сервер отдаёт картинки по прежним /media/… адресам, поэтому ссылки старых заказов сохраняются. Исходные иллюстрации в public/images остаются частью сборки.
- При загрузке фото ограничение 4 МБ, обработка sharp, WebP, проверка содержимого и размера.
- vercel.json, .vercelignore, Node.js 22, сертификат CA включён в трассировку серверных файлов.

## Перенос существующего магазина

Пользователь разрешил перенос всего текущего магазина, включая контакты заказов. Ключи сервисов и исходный пароль администратора в SQL не включаются; переносится актуальный хеш пароля из базы.

```sh
npm run supabase:export
```

Создаются закрытые .qa/supabase-source.sqlite, .qa/supabase-import.sql и счётчики строк. SQL-файл содержит контакты заказов: не публикуйте его и не отправляйте в чат.

Откройте SQL Editor своего проекта Supabase и выполните содержимое .qa/supabase-import.sql целиком. Файл проверяет пустую базу, переносит данные одной транзакцией и отклоняет повторный импорт. Старые локальные данные сохраняются. Не переносите отдельные таблицы вручную: снимки заказов, попытки оплаты, остатки и очередь должны оставаться согласованными.

На время окончательного переноса остановите локальное редактирование и новые заказы. После переноса не продолжайте изменять две независимые базы. Сессии администратора не копируются; актуальный пароль сохраняется. Покупательские cookies с localhost не дают автоматического доступа к старым заказам на новом домене; администратор видит историю заказов.

Прямой импорт также подготовлен: npm run supabase:migrate. Он использует Session pooler для миграции и сохраняет backup. В текущей сети длинные PostgreSQL-соединения прерываются после 19 коротких запросов; базовый SELECT 1 проходит, но этого недостаточно для проверки магазина. Два драйвера, TLS 1.2/1.3 и изменение фрагментации воспроизводили обрыв. Доступ к Storage по HTTPS работает. До устранения проблемы прямой импорт не подтверждён; используйте проверенный файл SQL Editor.

Фотографии переносятся отдельно:

```sh
npm run supabase:photos
```

Скрипт создаёт приватный bucket, переносит неизменяемые WebP и проверяет скачанные байты. Повторный запуск безопасен; локальные фото не удаляются.

## Настройки Vercel

Создайте проект Next.js из закрытого Git-репозитория либо через Vercel CLI. Секреты не включайте в исходники. В Environment Variables проекта задайте серверные переменные:

| Переменная | Значение |
|---|---|
| DB_DRIVER | supabase |
| STORAGE_DRIVER | supabase |
| PG_SCHEMA | shop |
| SUPABASE_URL | URL вашего проекта |
| DATABASE_URL | Transaction pooler, с URL-кодированным паролем |
| SUPABASE_CA_CERT_PATH | ./supabase-ca.crt |
| SUPABASE_SECRET_KEY | серверный Secret key или legacy service_role |
| SUPABASE_STORAGE_BUCKET | product-images |
| PAYMENT_MODE | yookassa_test |
| YOOKASSA_SHOP_ID | идентификатор тестового магазина |
| YOOKASSA_SECRET_KEY | только test_… |
| APP_URL | точный HTTPS-адрес размещённого магазина |
| EMAIL_MODE | resend (или disabled для изолированной проверки) |
| RESEND_API_KEY | серверный ключ Resend |
| EMAIL_FROM | разрешённый отправитель |

Для нового пустого магазина ADMIN_PASSWORD_HASH задаёт начальный хеш. При импорте аккаунта из SQLite актуальный хеш уже в базе, пересоздавать аккаунт не нужно. Не меняйте пароль сбросом локального .env: используйте вкладку «Доступ».

Build Command: npm run build. Install Command: npm ci. Framework: Next.js. Node.js: 22.x. Регион функций — dub1 (Дублин), рядом с текущим pooler eu-west-1. Источник: https://vercel.com/docs/regions.

Не задавайте DATABASE_PATH и UPLOADS_PATH для облачного магазина. Код откажется запускать SQLite/локальные фото на Vercel, если переключатели не настроены, чтобы данные не исчезали после перезапуска функции. DATABASE_URL и ключи не должны начинаться с NEXT_PUBLIC_. .vercelignore исключает .env*, .qa и data.

После присвоения адреса проверьте APP_URL и пересоберите развёртывание с актуальными переменными. Неверный Origin будет отклонён сервером. Для первого выпуска допускается отдельный demo, но он не должен выдаваться за проверенную ЮKassa.

## Публичная проверка тестовой оплаты

В тестовом магазине ЮKassa настройте https://ваш-адрес/api/payments/yookassa/webhook для payment.succeeded, payment.canceled и payment.waiting_for_capture. Открытие страницы успеха не подтверждает оплату: сервер сверяет API, сумму, валюту, получателя и metadata. Рабочие ключи отвергаются.

Проверьте: успех и отказ тестовой карты, отмену, повтор в том же заказе, повторное уведомление, отсутствие доступа из чужого браузера, письмо и сохранность остатков после повторного развёртывания. Проверьте свежие фотографии после перезапуска: они должны читаться из Storage.

Письма отправляются после подтверждённой оплаты через Next.js after и постоянную очередь; открытие оплаченного заказа повторяет безопасную попытку отправки. Для ручной сверки используйте npm run payments:sync и npm run mail:flush с облачными переменными. На Hobby cron ограничен запуском раз в день: нельзя переносить инструкцию VPS о запуске каждую минуту без изменения схемы. Источник: https://vercel.com/docs/cron-jobs/usage-and-pricing.

## Проверки и ограничения

Локальные 60 исходных тестов пройдены; добавлены 7 PostgreSQL-тестов на PGlite: расчёт, снимки и подмена суммы, права доступа, резервы, отмена/повтор, истечение demo, непротиворечивые статусы, редактор, пароль, почта и проверка API провайдера. SQL-файл проверен на чистом PostgreSQL-движке: каждое поле совпадает со снимком SQLite, права закрыты, повтор отклоняется.

Перенос в Supabase завершён: все поля сверены с локальным снимком, доступ публичных ролей закрыт. Сервер Vercel читает каталог и сохраняет заказы в PostgreSQL; реальная тестовая оплата подтверждена API ЮKassa. Публичный адрес, настройки и оставшиеся ограничения: [publication.md](./publication.md). Локальная база сохранена отдельно. Docker-файлы оставлены как альтернативный вариант для VPS.
